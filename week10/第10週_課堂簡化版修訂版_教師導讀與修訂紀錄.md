## 2. 與原課堂簡化版的差異

| 項目 | 原版 | 修訂版 | 理由 |
|---|---|---|---|
| 資料 | 第6／19格、第21格與App `activities.txt` 是四種寫法的「工作坊」文字；Notebook 3題、App 4題 | 全部改用**第9週sample.txt清理後的文字**（3段），Notebook與App共用同一組4題（原句／改寫／資訊未提供／文件外），附預期片段 | 「從第9週接入」名副其實；Notebook排名可直接和App對照 |
| 核心直覺 | 第7格只說「把文字變成可比較的數字」；第8格的手寫向量後面沒用到 | 第3節寫明「意思相近→向量方向接近」，用標明維度意義（地點、費用）的手寫向量，第4節直接算出「問地點」最接近哪一句 | 本週最重要的觀念要先講清楚，再進公式 |
| 離線對照 | 離線規則只跑一題 | 4題都跑，**改寫題（「哪個空間」）規則全零找不到**；demo_vector每組加註維度意義 | 讓學生親眼看到關鍵字比對的限制，再看真實Embedding |
| 沒有API時 | B的真實語意欄只能寫未測 | 新增7-2：教師課前用`SAVE_TEACHER_RECORD`存下`teacher_ranking_record.json`（日期、模型、排名，不含向量），學生讀取並標明「教師實測紀錄」 | 沒有API的學生也看得到語意搜尋效果；來源清楚，不是假結果 |
| B紀錄表 | 只有一列「自己填」 | 預先列出四種問題與參數比較共5列，加上「模式」欄（離線／自己API／教師實測） | 學生知道要交什麼，批改一致 |
| 第19格 | 重複貼一份chunks，且有兩行「用途」註解 | 改為依先備使用第2節資料，不再重複 | 整理合併殘留 |
| 語法說明 | 一段文字連續講zip、生成式、all、isfinite、any、dict、切片 | 改成「語法／在哪一行／做什麼」表格 | 好查、能對回程式 |
| A規格 | 5行連續文字 | 表格：已提供／你負責／輸入／回傳／保存變數／執行順序；自我檢查加一條「門檻很高只剩1筆」 | 與第9、13週修訂版一致 |
| 程式格開頭 | 「# 用途：…」 | 每格「# 用途：…；先備：…；請求次數」 | 明確要先跑哪幾格 |
| 真實API錯誤訊息 | 只顯示錯誤類型 | 顯示類型＋訊息 | 學生分得出缺金鑰還是模型名稱錯 |
| `.env`位置 | `student/.env`、`teacher/.env` 分開 | App資料夾一層共用`.env`（與第9、13週修訂版相同），入口資料夾的`.env`也讀得到；Notebook從`week10`讀App資料夾的`.env`；Cloud用Secrets；`student/`、`teacher/`同層附requirements | 跨週一致、學生只設一次；本機、Streamlit Cloud與Colab都能執行 |
| 用語 | 封面含「原教材保留」；斜線列舉、長句 | 學生版移除維護紀錄；環境說明改條列；請求次數改成口語句 | 適合朗讀與自讀 |

不變的部分：cosine_similarity與rank_chunks的程式邏輯、A為唯一程式TODO、離線預設0次API、真實模式每次有效提交1次、滑桿本機重排0次、成功才保存與失敗清舊結果、輸入上限（6000字元／12段／每段1000字元／問題300字元）、`max_retries=0`、timeout 60秒、40／30／20／10評量、作業45～60分鐘與繳交方式。demo_vector只在關鍵字清單加入「討論室」「每組」「網址」以配合新資料。

## 3. Notebook格次與課堂觀察

雙版各32格，只有封面、A答案與B教師提醒不同。每個程式格第一行寫用途、先備與請求次數；整本預設執行0次API。

| 格號 | 活動 | 教師引導與預期 |
|---|---|---|
| 1～4 | 目標、時間、環境 | 強調「本週只找資料，不回答」 |
| 5～6 | 從第9週接入 | 3段文字就是第9週sample.txt清理後的結果；4題與預期片段 |
| 7～12 | Embedding直覺、cosine、語法表、手寫向量計算 | 「問地點」對地點句約0.99、費用句約0.21、人數句約0.64：分數是相對的 |
| 13～16 | A與自我檢查 | 教師版印出「A通過」 |
| 17～20 | 離線規則對照 | 原句→chunk 0、改寫→找不到、費用→chunk 2、文件外→找不到 |
| 21～24 | 真實Embeddings（1次請求）與排名 | 課前實跑；重點看改寫題是否找到chunk 0、文件外題的最高分是否有原文支持 |
| 25～26 | 教師實測紀錄 | 沒有API時讀`teacher_ranking_record.json` |
| 27～28 | B與紀錄表 | 5列預填；區分「資訊未提供」與「文件外」 |
| 29～32 | App、作業、第11週銜接、檢核 | App預設文字與Notebook相同 |

## 4. 課前準備（建議）

1. 在本機開啟教師Notebook，設定`.env`後把第22格`RUN_REAL_EMBEDDINGS`改成True（1次請求），再把第24格`SAVE_TEACHER_RECORD`改成True，產生`teacher_ranking_record.json`。
2. 檢查紀錄中的排名，特別是改寫題與文件外題，準備課堂說明；這份檔案可發給沒有API的學生。
3. 改回False再發放教材，避免學生全選執行時誤觸付費請求（兩個開關預設都是False）。

## 6. 重建、驗證與已知邊界（2026-11-10）

重建來源為[scripts/build_week10_revised.py](../scripts/build_week10_revised.py)，檢查為[scripts/verify_week10_revised.py](../scripts/verify_week10_revised.py)。從Repo根目錄執行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/build_week10_revised.py
.\.venv\Scripts\python.exe -X utf8 scripts/verify_week10_revised.py
```

重建會讀取`week09/sample_tata/sample.txt`並套用第9週的清理規則產生預設文字，再產生雙版Notebook／Markdown、雙版App、`sample_data/`、`.env.example`、Secrets範本與requirements；不覆蓋本導讀與App README。

驗證內容：
- 資料延續：預設文字與第9週修訂版教師App的`clean_text(extract_text(sample.txt))`完全相同；questions.json與Notebook問題一致，預期證據確實在對應片段中。
- Notebook：32格JSON、唯一ID、清空輸出、每個程式格首行有用途與先備、語法、依先備獨立執行與順序執行、雙版只在封面／A／B提醒不同、三個函式與App AST一致、教師版離線結果為[[0], [], [2], []]、學生版A未完成時離線結果為None。
- 排名函式：方向與尺度、維度與有限數字、門檻／top_k／空結果、來源保留、原資料不變；改寫題與文件外題的規則向量全零。
- Notebook API（真實SDK＋MockTransport）：預設0次、開啟1次、合批7筆、index對齊（含反序回傳）、缺筆／重複／維度／全零／空／非數字／429／逾時都不保存且不重試、缺金鑰0次；教師紀錄存檔不含向量，7-2能讀回相同排名。
- AppTest：雙版啟動0次請求、預設文字＝第9週清理後文字、離線原句找到chunk 0、改寫題找不到、模擬真實模式1次、滑桿與rerun不重送、來源位置、各種API失敗與超限輸入清舊結果、清除、學生A未完成時0次請求、只移入A即成功。
- 重建一致、UTF-8、Markdown圍欄與本機連結。

驗證環境：Windows／CPython 3.14.0、Streamlit 1.60.0、OpenAI 2.49.0、python-dotenv 1.2.2、httpx 0.28.1（專案.venv）。requirements的Streamlit 1.63.0與python-dotenv 1.2.3為課程目標版本，不能稱為本次實測。

**本次真實API為0次。** 未驗證：真實Embedding對改寫題與文件外題的實際排名、模型與帳號權限、費用、真人瀏覽器、Colab、Cloud與課堂時長。`teacher_ranking_record.json`需教師課前實跑才會產生，本資料夾未附。
