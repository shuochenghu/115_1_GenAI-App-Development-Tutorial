# 第12週｜圖片理解與Vision・修訂版：教師導讀

本修訂版以原課堂簡化版（2026-11-03）為基礎另存。原版Notebook、`week12_vision_simple/`、原導讀與build／verify_week12_simple.py全部保留未改。
主線、A／B分工、單一App兩種任務、評量與作業最低要求都不變。修訂重點：
- 接上第11週，先講清楚本週流程，方法比較改成選讀。
- Notebook在`week12`資料夾開啟就能找到範例圖。
- 讓學生看見「送出前的content」。
- 讓沒有API的學生也看得到真實結果，B有工具幫忙找出要回看的地方。
- 金鑰在本機、Streamlit Cloud與Colab都能用；說明文字改得更適合課堂朗讀。

## 2. 與原課堂簡化版的差異

| 項目 | 原版 | 修訂版 | 理由 |
|---|---|---|---|
| 開場 | 第3格先放兩張方法比較表（送圖方式、任務做法） | 第2節「從文字到圖片」：接第11週，用五步驟表說明本週流程；方法比較移到第12節選讀 | 學生先知道本週要做什麼，再看其他做法 |
| 範例圖位置 | Notebook讀目前資料夾的`receipt_clear.png`；從`week12`開啟會找不到，只印「未測」 | `find_sample`先找`week12_vision_revised/sample_data`，再找目前資料夾（Colab上傳） | 打開就能跑，不必手動複製圖片 |
| 圖片處理說明 | 第7格6行長句 | 「檢查或處理／為什麼」表格 | 好讀、好朗讀 |
| A規格 | 4行文字 | content範例、Base64說明與規格表；自我檢查多一條「沒有改到image」 | 與第9～11、13週修訂版一致 |
| 送出前預覽 | 沒有 | `summarize_content`：Notebook與App都顯示content結構，Base64只留開頭與總字元數 | 學生看見模型真正收到的東西；App離線模式也有學習價值 |
| 送出 | Notebook兩格與App各自寫`responses.create` | 共用`ask_vision`（有schema時加strict JSON Schema，仍1次請求） | 少重複，Notebook與App AST一致 |
| Notebook示範 | 問答1題、抽取1張（只用清楚圖）；錯誤只印類型 | 問答2題（日期與總額／老闆姓名）、抽取2張（清楚／缺總額）；單題檢查失敗只記該題；錯誤印類型＋訊息 | B表四列都有真實資料；缺金鑰看得出原因 |
| 沒有API時 | 模型欄寫未測，老師另安排共看 | 新增第8節：`SAVE_TEACHER_RECORD`存`teacher_vision_record.json`（不含金鑰、原圖與Base64），學生讀取並標明來源 | 與第10、11週修訂版相同做法 |
| B | 2列「自己填」；教師提醒獨立成一格 | 判斷表（看錯／補造／格式失敗／合理看不到）、`b-compare`逐欄對照人工基準、預填5列；教師提醒併入B表 | 找得到要回看的地方，批改一致 |
| detail | 獨立一節 | 併入第6節兩句話與B的選做列 | 減少一節，重點不變 |
| App | 收據抽取時仍顯示問題欄（實際不使用） | 收據抽取只顯示固定任務；預設模式顯示送出前預覽與提示 | 避免學生以為改問題會影響抽取 |
| 金鑰與部署 | App讀Secrets與App資料夾`.env`；Notebook讀目前目錄`.env`並另開Colab格；入口同層沒有requirements | App：Secrets優先，再讀環境變數；先載入App資料夾`.env`，再載入入口資料夾`.env`。Notebook先讀App資料夾`.env`再往上找，Colab自動讀Secrets。`student/`、`teacher/`同層附requirements（含pillow） | 本機、Streamlit Cloud與Colab都能執行 |
| 請求次數 | 散在多格 | 第1節一張總表 | 不重複 |
| 程式格開頭 | 「# 先備：…」或無 | 每格「# 用途：…；先備：…；請求次數」 | 明確要先跑哪幾格 |
| 用語 | 封面含「原版保留」；長句與斜線列舉 | 學生版移除維護紀錄；條列、短句 | 適合朗讀與自讀 |

不變的部分：
- `prepare_image`、`read_answer`、`read_receipt`、`RECEIPT_SCHEMA`、`INSTRUCTIONS`、`RECEIPT_PROMPT`的內容。
- A的題目與參考答案，以及兩張範例圖與人工基準（逐位元複製）。
- 一次提交最多1次Responses，`max_retries=0`、timeout 60秒、`max_output_tokens=1200`、`store=False`。
- 評量40／30／20／10、作業45～60分鐘。

## 3. Notebook格次與課堂觀察

雙版各33格（18文字、15程式），只有封面、A答案與B教師提醒不同。每個程式格第一行寫用途、先備與請求次數；整本預設執行0次API。

| 格號 | 活動 | 教師引導與預期 |
|---|---|---|
| 1～4 | 目標、時間、環境與請求次數總表 | 強調圖片會傳到OpenAI，只用自製或授權圖片 |
| 5 | 從文字到圖片 | 和第11週對照：資料從文字變圖片，檢查與核對的習慣不變 |
| 6～8 | 準備圖片與預覽 | 兩張圖都是1000×800；送出PNG的SHA與原檔相同（原本就是PNG） |
| 9～13 | A、自我檢查、送出前預覽 | 教師版印出「A通過」；預覽可見圖片那一項約4.5萬字元 |
| 14～16 | 規則、回應檢查、金鑰設定 | 圖片裡的文字只是資料 |
| 17～18 | 圖片問答示範 | 課前實跑；看老闆姓名題是否承認無法確認 |
| 19～21 | 收據抽取示範 | 看缺總額圖total是否為null、warnings是否說明，是否用品項推算出300 |
| 22～24 | 教師實測紀錄 | 沒有API時讀`teacher_vision_record.json` |
| 25～27 | B判讀、逐欄對照、紀錄表 | 「不同」不一定錯（商家全名、日期格式），要回看原圖 |
| 28～29 | App與作業 | 收據抽取不顯示問題欄 |
| 30～31 | 選讀：其他送圖方式與處理方法 | 不要求實測 |
| 32～33 | 第13週銜接、檢核 | 圖片任務也可以看成一個工具 |

## 4. 課前準備（建議）

1. 在`week12/week12_vision_revised`設定`.env`。
2. 開啟教師Notebook，把第18格`RUN_VISION_API`、第21格`RUN_RECEIPT_API`改成True執行（共4次），再把第23格`SAVE_TEACHER_RECORD`改成True，產生`teacher_vision_record.json`。
3. 執行第26格逐欄對照，檢查缺總額圖的total、老闆姓名題的回答；若有檢查失敗，記下原因作為課堂例子。這份紀錄可發給沒有API的學生。
4. 三個開關改回False再發放教材。

## 6. 重建、驗證與已知邊界（2026-11-10）

重建來源為[scripts/build_week12_revised.py](../scripts/build_week12_revised.py)，檢查為[scripts/verify_week12_revised.py](../scripts/verify_week12_revised.py)。從Repo根目錄執行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/build_week12_revised.py
.\.venv\Scripts\python.exe -X utf8 scripts/verify_week12_revised.py
```

重建會產生雙版Notebook／Markdown、雙版App、設定範本與requirements，並從原簡化版逐位元複製範例圖與人工基準；不覆蓋本導讀與App README，不呼叫API。

驗證內容：
- 範例：兩張圖與`fixture_manifest.json`和原簡化版逐位元相同。
- Notebook：
  - 格式：33格JSON、唯一ID、清空輸出、每個程式格首行有用途與先備、Markdown沒有意外縮排。
  - 執行：依先備獨立執行與順序執行都通過；雙版只在封面、A、B提醒不同。
  - 對齊：6個函式與3個規則常數和App AST一致。
  - 範例位置：App資料夾與Colab（目前資料夾）兩種位置都找得到範例。
- 圖片與A：
  - 真實Pillow解碼四種格式；拒絕動畫、多影格、空檔、損壞與超限的圖。
  - EXIF轉正、不保留metadata、透明處補白底、轉換後大小上限。
  - Base64還原正確；`summarize_content`不改原資料，非data URL保持原樣。
  - Schema的缺值與型別檢查。
- Notebook API（真實SDK＋MockTransport）：
  - 請求次數：問答2題、抽取2張各1次。
  - 送出內容：送出的圖與記錄的SHA一致；`store=False`、`max_output_tokens`與strict Schema符合規格。
  - 付費前阻擋：A未完成、缺金鑰都是0次。
  - 失敗處理：拒答、未完成、缺status、空白、JSON與欄位錯誤只記該題；429與逾時整批不保存、不重試。
  - 教師紀錄：存檔後能讀回，不含金鑰與Base64；逐欄對照能把「缺總額圖回300」標成不同。
  - 網址與file_id兩種content形狀可序列化。
- AppTest：
  - 預設模式：雙版0請求，顯示送出前預覽；收據抽取不顯示問題欄。
  - 請求：只移入A即可通過；兩種任務每次1請求，rerun 0次。
  - 結果：缺值填null；送出的圖與預覽、SHA一致；用替代上傳器測過真實bytes。
  - 清除：各種API與檢查失敗、切換模式與清除都會移除舊結果與下載。
- 金鑰設定：
  - Secrets優先；沒有`secrets.toml`時讀環境變數。
  - App實際從入口資料夾或App資料夾的`.env`讀到金鑰，兩處都有時以App資料夾為準；Notebook讀App資料夾的`.env`。
  - 入口同層附requirements。
- 重建一致、UTF-8、Markdown圍欄與本機連結；`git status`確認原第12週檔案沒有修改。

驗證環境：Windows／CPython 3.14.0、Streamlit 1.60.0、OpenAI 2.49.0、python-dotenv 1.2.2、httpx 0.28.1、Pillow 12.3.0（專案.venv）。requirements的Streamlit 1.63.0與python-dotenv 1.2.3為課程目標版本，不能稱為本次實測。
