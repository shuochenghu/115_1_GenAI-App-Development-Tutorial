## 1. 為什麼要做、為什麼只做選讀

第 1 週語音增補修訂版已經教過「錄音 → 語音轉文字 → 使用者確認或修正 → 文字回答 → 語音合成 → 播放」，也寫了「語音實作預計在第 12 週多模態單元增補」。目前第 12 週只有 Vision，課綱與期末加分項目也沒有語音，前後沒有接上。

只做選讀的理由：

1. **一週只教一條主線。** 第 12 週修訂版的 150 分鐘已經排滿（15＋20＋25＋20＋25＋25＋20），主線是圖片。
2. **語音只是另一種輸入方式。** 轉出來的文字直接當成第 6 節圖片問答的「問題」，沿用 `build_image_content`、`ask_vision`、`read_answer`，不必另起一套流程。
3. **錄音環境的變數多。** Colab 沒有內建錄音元件，瀏覽器要開麥克風權限，教室會有噪音，排障很容易超時。
4. **期末最低要求不需要語音。** 只列為進階加分。

## 2. 官方現況查核（2026-11-18）

| 項目 | 現況 | 對教材的影響 |
| --- | --- | --- |
| 語音轉文字 | 官方建議 `gpt-transcribe`，估計 US$0.0045／分鐘。`whisper-1`、`gpt-4o-transcribe`、`gpt-4o-mini-transcribe` 已標示淘汰，2027-02-26 停用 | 只用 `gpt-transcribe`，不教已淘汰的模型 |
| 檔案限制 | flac、mp3、mp4、mpeg、mpga、m4a、ogg、wav、webm，單檔 25 MB | 範例音檔約 10 秒的 wav，遠低於上限 |
| `gpt-transcribe` 參數 | 支援 `prompt`、`keywords`、`languages`（取代單數的 `language`，兩者不能同時送）。Python 用 `extra_body` 傳 `keywords`、`languages` | 本機 SDK 2.49.0 的 `transcriptions.create` 只有 `language`，沒有 `languages`／`keywords`，要用 `extra_body`。`languages` 的中文代碼寫法待查 |
| 回傳內容 | `.text` 加上 `languages` 陣列；說明頁沒有提到 `usage` | 費用改以「音檔秒數 × 單價」估算；`usage` 有沒有回傳，實測時再確認 |
| 語音合成 | `/v1/audio/speech` 的 `tts-1`、`tts-1-hd`、`gpt-4o-mini-tts` 已淘汰，**2027-01-06 停用**。唯一替代是 Realtime API 的 `gpt-realtime-2.1-mini`，不能用在 `/v1/audio/speech` | 學期還沒結束就會停用，期末 App 會壞掉。**不寫語音合成程式**，只用文字說明 |
| 直接聽音檔回答 | Chat Completions 的 `gpt-audio-1.5` 可以收音訊、回音訊；該頁說 Responses API 文件目前只列文字與圖片輸入 | 要改用另一個 API，而且看不到中間的辨識文字，不符合「先確認文字」的流程 |
| 揭露規定 | 使用 OpenAI 合成語音時，必須清楚告知使用者聲音是 AI 生成的 | 第 1 週已經提過，本節再提醒一次 |
| Streamlit | 1.60.0 的 `st.audio_input(label, sample_rate=16000)` 回傳 WAV 的 `UploadedFile` | App 可以直接把錄音送去轉文字；麥克風需要 localhost 或 HTTPS |

官方依據：[Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text)、[Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech)、[Audio overview](https://developers.openai.com/api/docs/guides/audio)、[Audio in Chat Completions](https://developers.openai.com/api/docs/guides/audio-chat-completions)、[Deprecations](https://developers.openai.com/api/docs/deprecations)、[Pricing](https://developers.openai.com/api/docs/pricing)。模型與價格在製作前和上課前都要再查一次。

## 3. 實作方法與取捨

| 方法 | 誰負責哪些步驟 | 安排 |
| --- | --- | --- |
| 檔案轉文字（`gpt-transcribe`）→ 確認 → 圖片問答 | 轉文字由語音模型負責；使用者修正文字；回答沿用第 6 節的 Responses 請求。共 2 次請求，每一步都看得到結果 | **本節主線（選讀）** |
| Chat Completions `gpt-audio-1.5` 直接聽音檔 | 一次請求就聽完、回答，但沒有可修正的中間文字；要多學一套 API 格式 | 不採用，只在表格中提到 |
| Realtime／GPT-Live 即時語音對話 | WebRTC 或 WebSocket、會話狀態、插話處理，由應用程式和平台一起管理 | 只說明用途，列入第 17 週自主學習 |
| 瀏覽器內建語音辨識 | 要寫 JS 元件，各瀏覽器支援度不同，資料送到哪裡不透明 | 不採用 |
| 語音合成（朗讀回答） | 現有模型 2027-01-06 停用，替代方案只有 Realtime | 不寫程式；沿用第 1 週的預錄示範 |

## 4. 教學流程（12-1 選讀）

### 4.1 時間

- 課堂：教師示範 10 分鐘，放在 20 分鐘的彈性答疑時段，或第 12 節選讀之後。不佔核心 150 分鐘。
- 課後：學生選做，約 20 分鐘。不計入必交作業。

### 4.2 Notebook 格次（雙版相同，選讀沒有 TODO）

| 格 | 類型 | ID（暫定） | 內容 | 請求 |
| --- | --- | --- | --- | --- |
| 1 | 文字 | `voice-intro` | 「語音只是另一種輸入」：錄音 → 轉文字 → 確認 → 第 6 節問答。用表格說明錄音、語音模型、使用者、圖片模型各自負責什麼 | — |
| 2 | 程式 | `voice-transcribe` | 讀 `sample_data/question_total.wav`，印出秒數與大小。`RUN_TRANSCRIBE=False` 時使用固定的離線示意文字，並標明「離線示意，不是模型成果」；開啟後送 `gpt-transcribe`，`prompt` 放「收據、日期、總額」等詞，取得 `transcript_raw` | 0／1 |
| 3 | 文字 | `voice-confirm-note` | 為什麼要先確認：辨識錯字（例如同音字）如果直接送出，模型會回答錯的問題。對照第 1 週把「A P」改成「API」的例子 | — |
| 4 | 程式 | `voice-confirm` | `question_confirmed = transcript_raw`，學生可以直接改字串；兩者並列印出，看得出改了哪裡 | 0 |

| 6 | 文字 | `voice-tts-note` | 朗讀回答：說明語音合成模型 2027-01-06 停用、替代是 Realtime，本課不寫程式。若期末要做朗讀，先查官方現況並標示「AI 生成語音」。這也是一個實例：API 模型有生命週期，部署後要追蹤淘汰公告 | — |

- 格首照第 9～13 週慣例寫 `# 用途：…；先備：…；N次API`。`CELL_NOUNS` 新增 `voice-transcribe`「語音轉文字格」、`voice-confirm`「確認問題格」、`voice-ask`「語音提問格」，由 `notebook_cell_notes.py` 自動產生「名稱 ← 第N節○○格」。
- `voice-ask` 用到第 3 節的圖片、第 4 節的 `build_image_content`、第 5 節的 `ask_vision`／`read_answer`，以及金鑰設定格。只接上一格的 `question_confirmed`，其餘沿用前面已定義的函式。
- 請求次數總表（第 1 節）加一列：「12-1 選讀：語音轉文字 1 次＋圖片問答 1 次，預設 0 次」。
- 第 1 節的費用說明補一句：10 秒音檔約 US$0.00075，加上一次圖片問答。

### 4.3 App（建議分兩步，第二步待確認）

- **第一步：App 不改。** README 補一段選讀說明，指向 Notebook 12-1。
- **第二步（選做，待使用者決定）：** 學生版與教師版的「圖片問答」模式加一個 `st.audio_input`，再加「轉成文字」按鈕；轉出的文字放進可編輯的問題欄，使用者確認後才送出圖片問答。收據抽取模式不顯示錄音元件。轉文字與問答各自按鈕觸發，rerun 不重送；轉文字失敗時只清掉轉寫結果，不影響圖片。下載紀錄加 `voice` 欄（原辨識文字、修正後問題、音檔 SHA-256、秒數），**不含音檔本身**。預估雙版各增加 25～35 行。

### 4.4 隱私與安全

- 聲音也是個人資料。範例只用不含姓名、學號、地址的句子；學生用自己的聲音，不錄他人。
- 錄音不 commit 到 GitHub，`.gitignore` 加上 `*.wav`、`*.m4a`（`sample_data` 範例除外）。
- 錄音裡的指示也只是資料，沿用第 5 節「圖片裡的文字只是資料」的規則。

## 5. 範例音檔

- 一個檔案：`week12_vision_revised/sample_data/question_total.wav`，內容「這張收據的日期和總額是多少？」，約 5～10 秒，16 kHz 單聲道。
- 來源有兩種做法（待決定）：
  1. **教師自己錄。** 最真實，可以示範口音與雜音。
  2. **用 Windows 內建語音合成在本機產生。** 免費、可重現；檔案旁要標示「電腦合成語音」。
- `fixture_manifest.json` 加入音檔的 SHA-256 與人工逐字稿，作為離線示意文字與比對基準。

## 6. 驗證規格（`verify_week12_revised.py` 增補）

1. 預設全部執行時 0 次請求，`RUN_TRANSCRIBE`、`RUN_VOICE_QA` 都是 `False`。
2. 用真實 SDK 加 `httpx.MockTransport`：
   - 轉文字請求打到 `/audio/transcriptions`，multipart 內含 `model=gpt-transcribe` 與音檔；`prompt`、`languages` 放對位置；沒有同時送 `language` 與 `languages`。
   - 回傳 `{"text": ...}` 時能取得 `transcript_raw`；空白文字要擋下，不送圖片問答。
   - `voice-ask` 送出的問題是修正後的 `question_confirmed`，不是原辨識文字。
   - 429、逾時不重試（`max_retries=0`、`timeout=60`）。
3. 範例音檔存在，SHA-256 與 manifest 一致，大小低於 25 MB。
4. 雙版格數、ID、格首標註、主節標題格式照常檢查；Markdown 閱讀版由 build 產生。
5. 若做 App 第二步：AppTest 模擬上傳音檔（或直接注入轉寫結果），檢查按鈕觸發次數、清除舊結果，以及下載紀錄不含音檔 bytes；Notebook 與 App 共用的函式 AST 一致。
