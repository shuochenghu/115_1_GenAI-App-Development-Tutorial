# 生成式AI應用開發 第01週教材｜語音增補修訂版

## 一、本週主題

課程導論與生成式AI應用架構

本週不要求學生撰寫程式，也不使用付費 API。語音部分以預錄／預先產生素材示範，認識語音辨識、文字回答與語音合成的分工。重點是讓學生理解本課程要培養的能力、生成式AI應用的基本組成，以及後續 18 週會如何逐步完成一個可部署的 AI Web App。

## 二、學習目標

學生完成本週課程後，應能：

1. 說明本課程與「生成式AI理論與實務」的差異。
2. 區分 ChatGPT 類網頁工具與 LLM API 應用開發的差異。
3. 說明一個生成式AI應用的基本架構。
4. 初步理解 Prompt、Structured Outputs、RAG、Vision、語音辨識／合成、Tool Calling、Agent、Skill、MCP、部署等概念在課程中的位置。
5. 理解本課程的工具、評量方式、期中與期末專題要求。
6. 理解 Git、GitHub 與 GitHub Desktop 在本課程專題開發中的用途。
7. 完成開發環境與帳號準備清單的確認。
8. 說明語音辨識（STT）、模型文字回應與語音合成（TTS）的分工，指出辨識錯誤的修正位置。

## 三、課前準備

教師準備：

- 課程大綱 Markdown 或 PDF。
- OpenAI、Claude、Gemini 網頁版展示帳號。
- 一至兩個 AI Web App 範例，可使用公開 demo 或教師自製簡易展示。
- 一段無個資的預錄提問、辨識文字、文字回答及事先準備的合成音訊；音訊旁標示「AI生成語音」。未備妥音訊時，使用第十一節的文字流程演練，明示沒有實際播放。
- 電腦教室環境檢查清單，另確認教師端喇叭可播放。
- 學生背景調查表單，例如 Python 程度、是否有 GitHub 帳號、是否用過 ChatGPT API。

學生準備：

- 可登入學校電腦或自備筆電。
- 可使用瀏覽器。
- 建議先註冊 GitHub 帳號。
- 本週不需準備 API key、麥克風或耳機；設備狀況先填背景調查，後續語音實作可用提供的音檔。

### Slide 7：AI 應用的輸入與輸出

| 資料形式 | 輸入範例 | 輸出／處理範例 |
|---|---|---|
| 文字 | 問題、文件內容 | 回答、摘要、JSON |
| 圖片 | 截圖、收據照片 | 圖片說明、欄位抽取 |
| 語音 | 錄音、口頭問題 | 辨識文字、回答朗讀 |

- **語音辨識（STT）**：把音檔轉成文字
- **語音合成（TTS）**：把文字轉成可播放的音訊

> 錄音、辨識、合成、播放是不同步驟。


**示範提問**：請用生活中的例子解釋什麼是 API。

- 畫面保留辨識文字與回答，方便核對
- 本課程先學分段處理，每段可分別檢查錯誤與用量
- 第 5 週 Streaming 是**文字片段**，語音合成是後續步驟

### Slide 10：什麼是 RAG？

**RAG = Retrieval-Augmented Generation**
讓模型根據**你的資料**回答問題，而非只依靠訓練知識

```
文件資料
  → 切分段落
  → 建立向量 Embedding
  → 查詢相關段落
  → 將段落放入 Prompt
  → 模型根據資料回答
```

**課程應用範例**
校園課程問答、企業文件知識庫、法規查詢系統

### Slide 11：什麼是 Agent？

Agent 讓模型根據**任務目標**自行決定步驟，並呼叫工具完成多步驟任務

```
目標輸入
  → 思考下一步
  → 選擇工具
  → 執行工具
  → 觀察結果
  → 繼續或完成
```

本課程路徑：**Function Calling（Week 13）→ Agent Loop（Week 14）**

### Slide 12：Skill 在本課程中的角色

本課程**不重教** Claude Desktop Skill 操作

本學期重點是：

- 把 Skill 視為**可重複使用的任務模組**
- 將任務說明、輸入 / 輸出格式、工具規則封裝成 **Python 函式**
- 讓 Streamlit App 或 Agent 呼叫這些模組

**範例模組**
會議紀錄整理、客服回覆草稿、履歷分析、CSV 資料摘要

### Slide 13：什麼是 MCP？

**MCP（Model Context Protocol）**
讓 AI App 或 Agent 以**標準方式**連接外部工具與資料來源的協定

本課程定位：

- 第15週概念說明與示範
- 不要求全班從零撰寫 MCP Server
- 可作為**期末專題進階加分項目**

### Slide 18：API 金鑰安全守則

- **不要**把 API key 寫在程式碼中
- **不要**把含有 API key 的檔案上傳到 GitHub
- 使用 `.env` 或 Streamlit secrets 管理金鑰

```python
# ❌ 錯誤做法
client = OpenAI(api_key="sk-abc123...")

# ✅ 正確做法
import os
from dotenv import load_dotenv
load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
```

## 六、Git 與 GitHub 教學定位說明

### 本週定位：概念說明 + 帳號準備（10 分鐘）

Week 2–6 學生使用 Google Colab / Notebook，不需要版本控制。Week 7 切換至 VS Code + Streamlit 開發實際專案時，才是學習 Git 操作最自然的時機——學生有真實程式碼可以 commit，且可在同一堂課直接部署到 Streamlit Cloud，讓 Git 的用途立刻顯現。

因此本週 Git 章節的目標僅有兩項：

1. **讓學生理解為什麼本課程需要 Git 與 GitHub**
2. **完成帳號建立與工具安裝，Week 7 不再花時間處理環境**

完整 Git 實作教學（建立 repo、commit、push、部署）安排於 **Week 7**。

### 本週教師說明重點

向學生說明以下三件事即可：

- Git 是記錄程式修改歷史的工具，GitHub 是存放程式碼的雲端平台。
- 期中與期末專題都必須有 GitHub repository 與 README，部署也透過 GitHub。

## 七、教師講稿重點

### 開場

這門課不是教大家如何訓練一個大型語言模型，而是教大家如何把大型語言模型接進資訊系統。未來在企業裡，多數資管背景的人不一定會自己訓練模型，但很可能需要把模型 API、資料庫、文件、Web 系統與企業流程整合起來。

### 課程定位

本課程的核心能力是 AI application development。你們會從 Python API 呼叫開始，逐步做到 Web App、RAG、圖片理解、工具呼叫與 Agent。期末要完成的是一個別人可以打開網址使用的應用，而不是只在 Notebook 裡跑一段程式。

### 平台選擇

課程主線使用 OpenAI API，原因是教材、範例、生態與初學者支援較完整。Claude 與 Gemini 不會被忽略，但會放在比較與自主學習階段，避免一開始被不同平台語法分散焦點。

### Skill 銜接

上學期已經學過 Skill 架構與 Claude Desktop 使用方式。本學期會把 Skill 的思維放進應用開發：如何把一個任務能力變成可重複使用的 Python 模組，讓 Web App 或 Agent 呼叫。

### 期末期待

期末專題不是比誰用最多模型，而是看能不能解決一個明確問題。好的專題應該有清楚的使用者、清楚的資料來源、穩定的操作介面、合理的錯誤處理，以及對成本與限制的說明。

## 十一、語音應用示範與完成檢核

### 10分鐘示範腳本

本節文字是固定的離線教學素材，不是現場API成果。教師可提前準備對應音訊；只有文字時稱為「流程演練」，不宣稱已完成語音播放。

| 分鐘 | 教師操作 | 學生觀察 |
|---|---|---|
| 0–1 | 播放預錄提問：「請用生活中的例子解釋什麼是API。」 | 輸入是音檔 |
| 1–3 | 顯示示意辨識結果「請用生活中的例子解釋什麼是A P」，讓學生改為「API」 | 辨識文字可以確認、修正 |
| 3–5 | 顯示下方示意回答，指出模型接收的是修正後文字 | 語音辨識與回答生成是不同步驟 |
| 5–7 | 播放事先準備的回答音訊，保留同一份回答文字 | TTS讀取回答文字，播放器呈現音訊 |
| 7–10 | 討論辨識錯誤、回答錯誤與播放失敗各在哪一段檢查 | 分開判斷錯誤來源 |

示意回答：「API像餐廳的點餐窗口。你依規定送出訂單，窗口把需求交給廚房，再把結果交回來。程式也能透過API向服務提出請求並取得結果。」

教師備援：若無音訊，讀出提問並出示文字素材，讓學生完成流程排序與修正討論。這仍能檢核概念，但不能當作STT／TTS實跑證據。

### 學生檢核與教師判讀

- 能指出STT輸出是文字、TTS輸出是音訊，錄音與播放各有自己的責任。
- 能把「A P」改為「API」後才交給模型，不用TTS掩蓋辨識錯誤。
- 能說明第5週文字Streaming與語音合成的差別。入門語音流程先取得完整可用回答，再按鈕觸發朗讀。
- 能說明第6週Structured Outputs處理文字資料；後續可以抽取已確認的逐字稿。JSON符合格式仍要回看辨識文字及原錄音。
- 提交一張流程圖及一句錯誤修正說明即可，無須交付音檔或新增API呼叫。

### 後續銜接與成本

第5、6週繼續使用Colab學文字對話與資料抽取，第7週建立Web介面。語音辨識與合成預計在第12週多模態單元增補，實作教材尚待製作；本次不代表其他週教材已更新。

語音辨識、文字模型與語音合成分段記錄用量，各依所選服務的計費方式估算。STT、回答或TTS失敗應分段重試，不自動重跑整條流程。語音範例只用無個資素材，播放合成音訊時標示「AI生成語音」。

參考：[OpenAI語音工作流程](https://developers.openai.com/api/docs/guides/voice-agents)與[語音合成及AI語音揭露說明](https://developers.openai.com/api/docs/guides/text-to-speech)。本週只介紹分段架構，不指定語音模型或API參數。
