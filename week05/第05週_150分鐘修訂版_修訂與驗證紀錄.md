## 修訂決策

1. 接回第四周：固定人工few-shot範例與真實對話history使用相同訊息結構，但來源與目的不同。
2. 主線改為手動history，固定instructions每輪送出；非串流與串流共用state、最近N輪組裝與成功配對保存，銜接第七周最近五輪聊天App。
3. `previous_response_id`保留為兩輪比較示範，不要求再完成一套完整聊天工具；Conversations API只保留概念。
4. 必做A使用函式及list/dict完成最近N輪、reset；必做B在事件迴圈累積文字與計數，不使用繼承、super或nonlocal。
5. callback以具名def接回第四周函式參數概念；類別封裝、重要事實與互動CLI移至延伸。
6. 配合150分鐘安排邊教邊做，不把兩題必做練習壓在最後15分鐘；明訂產出與離線排障替代活動。
7. 非串流先檢查完成狀態、拒答及非空文字；串流明確處理error、failed、incomplete與缺少completed。所有檢查通過後才保存user/assistant配對。
8. 裁切只控制送入模型的context，本機history仍保留全部；reset清除本機state，不刪除平台已保存response或帳單。
9. usage與成功請求數只統計成功回合；不是包含失敗／中斷的完整帳單。字元數、delta數及tokens分開說明。
10. 第六周保留Structured Outputs；第七周原教材及App不改動。

## 執行與請求數

所有付費旗標預設False，互動CLI呼叫預設註解。可先安裝SDK、執行函式與離線示範，不需API key。SDK安裝會連線，不等於LLM呼叫。

| 旗標／活動 | 執行前條件 | 模型請求數 |
|---|---|---:|
| RUN_STATELESS_DEMO | 設定金鑰 | 2 |
| RUN_MANUAL_DEMO | 設定金鑰 | 2 |
| RUN_ID_COMPARISON | 設定金鑰，接受store=True比較 | 2 |
| RUN_INPUT_CHECK | 完成練習A | 0 |
| RUN_PRACTICE_A | 完成A，設定金鑰 | 3 |
| RUN_STREAM_DEMO | 完成A/B，設定金鑰 | 1 |
| RUN_PRACTICE_B | 完成A/B，設定金鑰 | 2 |
| RUN_OFFLINE_CHECKS | 完成A/B | 0 |
| RUN_LIVE_TESTS | 完成A，設定金鑰 | 3 |
| CLI | 完成A/B，手動開啟 | 每次正常發問1次 |

所有固定付費活動各執行一次共15次請求，不含額外重跑、挑戰題或CLI。可省略RUN_STREAM_DEMO並直接做練習B，省去重複示範。費用仍需依實際usage及上課時模型價格估算。

學生須先完成對應練習，再開啟依賴它的旗標；未完成骨架會明確拋出NotImplementedError，不以空值假裝成功。老師可先用教師版演示，同時保留學生修改與觀察時間。
