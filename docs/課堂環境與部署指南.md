# 第 7–11 週課堂環境與部署指南

本指南供教師準備電腦教室、學生重建本機環境，以及部署 Streamlit 專題時使用。課堂以 **Python 3.12** 為基準；先讓全班使用相同且經過測試的套件組合，再安排模型與 API 功能測試。

## 1. 課堂版本基準

驗證日期：**2026-09-16**。本機測試平台：**Windows x86_64、CPython 3.12.13**。

| 直接依賴 | 固定版本 | 用途 |
|---|---|---|
| Streamlit | 1.63.0 | 第 7–11 週 Web App |
| OpenAI SDK | 2.49.0 | Responses API 與 Embeddings API |
| python-dotenv | 1.2.3 | 本機 `.env` 設定 |
| NumPy | 2.5.3 | 向量與相似度運算 |
| pandas | 3.0.5 | CSV 讀取與資料整理 |
| pypdf | 6.18.1 | PDF 文字抽取 |
| python-docx | 1.2.0 | Word 段落與表格抽取 |
| ChromaDB | 1.5.9 | 第 10 週選讀、第 11 週正式索引 |

各 App 的 `requirements.txt` 只列該 App 必要的直接依賴，並固定版本；第 10 週的 `requirements-chroma.txt` 另外包含 ChromaDB 選讀依賴。

[完整 Windows 課堂快照](../environments/classroom-windows-py312.txt)包含直接依賴及套件再依賴的其他套件。它供同平台重現與安裝限制使用；不要把 Windows 快照直接當成 macOS、Linux、Colab 或 Community Cloud 的完整鎖定檔。

固定直接依賴仍可能讓間接依賴隨安裝日期改變。要重現這次課堂組合，請用完整快照；只有 `pip install -r requirements.txt` 時，應再次檢核相依性與 App 行為。

## 2. 教室準備：重建整組測試環境

先安裝 Python 3.12。以下從**整個課程 repo 根目錄**執行，使用 `.venv-classroom`，避免覆蓋其他用途的虛擬環境。

Windows PowerShell：

```powershell
py -3.12 -m venv .venv-classroom
.\.venv-classroom\Scripts\python.exe -m pip install -r environments/classroom-windows-py312.txt
.\.venv-classroom\Scripts\python.exe -m pip check
.\.venv-classroom\Scripts\python.exe --version
.\.venv-classroom\Scripts\python.exe scripts/verify_classroom_environment.py
```

快照的 Python 實測版本是 3.12.13；`py -3.12` 選取電腦已安裝的 3.12，不保證修補版本相同。教師應記錄 `python --version` 的輸出；若有差異，重新跑檢核，勿直接宣稱與測試環境完全相同。

`.venv-classroom` 是本機產物，不可提交到 Git。若使用其他虛擬環境名稱，也要在自己的 `.gitignore` 排除。

## 3. 學生準備：單一 App 與完整課程 repo

六個正式 App：

| App | 課程 repo 中的目錄 |
|---|---|
| 第 7 週 Streamlit | `week07/week07_streamlit_app` |
| 第 8 週學生 starter | `week08/week08_midterm_starter` |
| 第 8 週教師 demo | `week08/week08_midterm_example_summarizer` |
| 第 9 週文件處理 | `week09/week09_document_processor` |
| 第 10 週語意搜尋 | `week10/week10_semantic_search_app` |
| 第 11 週 RAG | `week11/week11_rag_app` |

每個 App 的 README 都提供 Python 3.12 虛擬環境的建立方法。請先進入目標 App 資料夾，再安裝套件與啟動：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip check
python -m streamlit run app.py
```

若 PowerShell 不允許執行啟用腳本，可直接使用 `.\.venv\Scripts\python.exe` 取代上述 `python`，不必變更系統執行原則。

如果保留**整個課程 repo**，且電腦也是 Windows / Python 3.12，可在 App 資料夾改用以下指令，只安裝本週必要套件，同時限制間接依賴符合課堂快照：

```powershell
python -m pip install -r requirements.txt -c ../../environments/classroom-windows-py312.txt
python -m pip check
```

第 10 週選讀 ChromaDB 時使用：

```powershell
python -m pip install -r requirements-chroma.txt -c ../../environments/classroom-windows-py312.txt
```

`-c` 是版本限制清單，不會把清單中所有套件都裝進去。如果只複製單一 App，`../../environments` 就不存在；請依該 App 的 `requirements.txt` 安裝，或把課堂快照另存為本機檔案後調整 `-c` 路徑。

macOS / Linux 使用 `python3.12 -m venv .venv` 與 `source .venv/bin/activate`，再安裝各 App 的 `requirements.txt`。這些平台尚未完成本次實跑驗證。

## 4. 工作目錄、設定檔與啟動路徑

以第 11 週為例：

| 情境 | 工作目錄 | 指令／入口 |
|---|---|---|
| 本機在 App 中工作 | `week11/week11_rag_app` | `python -m streamlit run app.py` |
| 本機模擬整個 repo 部署 | 課程 repo 根目錄 | `python -m streamlit run week11/week11_rag_app/app.py` |
| Community Cloud 部署整個 repo | 平台從 repo 根目錄啟動 | Main file path：`week11/week11_rag_app/app.py` |
| 把 App 內容獨立成 repo | 新 repo 根目錄 | Main file path：`app.py` |

本機指令中的 `python` 必須來自已安裝套件的虛擬環境。使用教室共用環境時，也可以從課程 repo 根目錄直接執行：

```powershell
.\.venv-classroom\Scripts\python.exe -m streamlit run week11/week11_rag_app/app.py
```

### 設定檔不必全部搬到 repo 根目錄

Streamlit 1.46 起已支援依入口程式位置搜尋設定；本課程固定的 **1.63.0** 支援這個行為。設定優先順序由高至低為：命令列參數、環境變數、入口程式旁的 `.streamlit/config.toml`、目前工作目錄的 `.streamlit/config.toml`、使用者全域設定。[官方發布紀錄](https://docs.streamlit.io/develop/quick-reference/release-notes/2025)

第 9–11 週各自保留 App 旁的 `.streamlit/config.toml`。從 repo 根目錄啟動時，也會載入該 App 的設定；第 11 週的主題設定因此可以獨立管理。第 7、8 週目前沒有自訂 `config.toml`，採預設設定。

Community Cloud 的[檔案配置頁](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/file-organization)仍寫設定應在 repo 根目錄，與新版入口目錄搜尋行為有出入。本指南依固定版本的本機 CLI／設定載入驗證撰寫；真正雲端部署後仍要確認套件版本、主題與上傳限制，不把本機結果當成雲端實測。

`requirements.txt` 保持在各 App 的 `app.py` 同一目錄，Community Cloud 可依入口選取該 App 的依賴。不要在相同部署位置混放多種套件管理檔，造成平台選用另一份依賴清單。[官方依賴檔規則](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies)

## 5. 上傳限制與金鑰位置

第 9–11 週有三個對齊的設定：

1. `st.file_uploader()` 明確傳入 8 MB 的 `max_upload_size`，讓上傳元件使用固定上限。
2. App 取得檔案後，以 `8 * 1024 * 1024` bytes 再次檢查。
3. 各 App 的 `.streamlit/config.toml` 保留 `server.maxUploadSize = 8`。

明確的 `max_upload_size` 會覆蓋該元件的全域上傳上限；日後調整時要同步修改三者。本次實測接受恰好 8 × 1024 × 1024 bytes，超過 1 byte 會顯示超限訊息。第 7 週與第 8 週教師 demo 的文字檔上傳未加入這項 8 MB 限制，第 8 週 starter 本身沒有上傳器。[上傳元件文件](https://docs.streamlit.io/develop/api-reference/widgets/st.file_uploader)

本機金鑰放在 App 目錄的 `.env` 或 `.streamlit/secrets.toml`；範例檔可以提交，真實金鑰檔不可提交。部署時把 `.streamlit/secrets.example.toml` 的項目填入 Community Cloud 的 Secrets，不上傳 `.env`。

## 6. Community Cloud 部署檢核

1. 選擇整個課程 repo 或自己的獨立專題 repo，依上表設定 Main file path；平台路徑使用 `/`。
2. 在部署的 Advanced settings 選擇 **Python 3.12**，填入 Secrets。若平台無法選取此版本，先在可用版本建立新測試基準，再更新教材。[官方部署步驟](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy)
3. 確認平台安裝的是入口旁的 `requirements.txt`，且 Streamlit 為 **1.63.0**。平台可以選擇 Python 次版本，但修補版本可能與本機不同。
4. 開啟畫面，確認沒有套件匯入錯誤；第 11 週確認主題，第 9–11 週確認上傳元件顯示 8 MB。
5. 上傳無敏感資料的小檔、恰好 8 MB 與超限檔，確認處理與拒絕結果。
6. 第 9 週測試預覽／下載；第 10、11 週以離線模式建立索引、查詢與顯示來源。
7. 最後才使用測試用金鑰確認 API 功能；這一步會產生學生個人帳號費用，請先確認預算。

新建雲端環境會解析 Linux 適用的間接依賴，因此這份部署清單必須實際執行。不要用 Windows `pip freeze` 成功，推論雲端一定可以安裝。

## 8. 開課前或升級套件時

先在新的虛擬環境驗證，再同步更新各 App 的直接依賴、完整快照、Notebook 安裝段落與本指南日期／版本表。保留測試結果與仍待確認的項目。學期中避免讓未指定版本的安裝指令任意升級；Streamlit 官方也建議固定版本。[版本管理說明](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app)
