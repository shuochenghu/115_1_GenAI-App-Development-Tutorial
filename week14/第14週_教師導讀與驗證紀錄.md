## 2 開場與責任分工

先問：「第一次搜尋的資料還沒回答問題，下一步要換字詞、讀原文，還是承認不足？」讓學生先說人會怎麼做，再介紹planning、tool use、observation、final answer及stop。

| 誰 | 責任 | 帶課時要指出 |
|---|---|---|
| 使用者 | 問題、官方範圍 | scope由人定，不能被模型更換 |
| 外層模型 | 選搜尋、閱讀或回答 | planning由工具與參數觀察，不要求輸出隱藏推理 |
| Python | 驗提案、A停止規則、硬上限及分派 | 模型提出不代表已執行；程式也不是eval模型字串 |
| 搜尋後端 | 一次內建web_search | 另有一次Responses費用，和外層分開 |
| HTML閱讀工具 | 讀已登記官方頁面 | 搜尋摘要不是原文；一般HTTP不是OpenAI API |
| 人工查核 | 主張、原文、版本及日期 | 格式與來源通過仍可能答錯 |

第13週build_search_task仍只準備規格。本週search_official把規格與真正搜尋包成可選工具；read_official_page新增一般HTML讀取。Skill-like文件只是設計說明，API不會自動載入。

## 5 A與B的帶課提醒

A：tool_count是「已用」而不是「下一次的序號」。2／3可放行，3／3已滿；同時重複與達上限，先回tool_limit。只print沒有return會使檢查失敗。教師答案只在教師版，學生版保留NotImplementedError。

B：要能指出具體主張與原文短句、適用條件，以及一個版本／日期／數字。學生只寫「有網址所以正確」不算查核。若excerpt截取了，打開原頁看被截掉的部分；讀不到時誠實寫工具限制，不能推論不存在。

虛構判讀示意：若回答說「所有操作都立即提交」，學生應用實際原文的條件逐項比對，再說支持／部分支持／不支持。本導讀不把這句當真實模型輸出，也不替學生填入個人的API紀錄。

## 6 控制、成本與狀態

硬上限：外層4輪、工具總3次、搜尋2次、閱讀2次、Responses總6次。典型搜尋→閱讀→回答為4次Responses＋1次內建搜尋＋1次HTTP；換一次字詞後再讀取可達6次Responses。每題各欄上限並非都可同時用滿。

模型可提早回答或說明不足；不以走滿步數評分。最後一輪不提供工具，相同動作執行前停止；scope、主機、來源代號及工具名稱都由程式查核。API使用max_retries=0、timeout=60、store=False；內建搜尋max_tool_calls=1。搜尋後端如有未完成回應，仍保留已回傳的內建工具事件。

正常／不足兩題最多12次Responses、4次內建搜尋與4次HTTP；課堂與作業成果可合用，額外提交另計。真實請求須由操作人主動開啟；讀回及rerun不加費。逾時不保證服務端沒有處理或計費。

HTML讀取限已登記的精確官方HTTPS主機、443埠、1MB、10秒網路等待及6000字元片段，不跟轉址、不跑JavaScript。query保留，fragment去除；這項新週設計不代表本次修改了第13週既有來源比較方式。

新題、範圍／模式／模型切換、清除或失敗都不保留舊成功答案。成功／不足的final有三欄；stopped的final為None，可下載失敗trace。reasoning只供SDK回送，不顯示、不匯出。沒有API或HTTP真實連線時不能把MockTransport或手寫情境當成果。

它檢查：schema、模式、上限、UTC時間、工具白名單、call_id及順序、來源先搜尋再閱讀、原文片段雜湊、最後引用、逐步與總計、停止後無新事件及失敗不帶成功答案。它不驗真實來源簽章、不證明學生身分，不會自動判斷語意支持度；前後一致的偽造資料仍可能通過。

## 8 環境、生成來源與離線驗證

生成來源：[build_week14.py](../scripts/build_week14.py)＋[核心模板](../scripts/templates/week14_agent_core.py)；檢查：[verify_week14.py](../scripts/verify_week14.py)。

```powershell

.\.venv\Scripts\python.exe -X utf8 scripts/verify_week14.py
```

驗證腳本隔離OPENAI_*、停用讀.env／Secrets、禁止socket連外，使用真正SDK＋httpx.MockTransport，不把假client放進學生教材。檢查內容：

- JSON、48個唯一ID、清空輸出、程式語法、章節、預設旗標、學生／教師答案分離、逐格獨立先備與順序執行、共用函式AST及閱讀版同步。

- 外層與搜尋後端請求、完整output及call_id回送、Structured Outputs規格、最大6次路徑、最後輪次禁工具、重查／重複／上限、逾時／429不重試。

- 雙版AppTest及只補入A的學生版：零請求啟動、預檢、成功、rerun、清除、模式／範圍切換、失敗清舊答案、session隔離與成功／失敗下載。
